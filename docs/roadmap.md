# 로드맵과 첫 오픈 범위

> 무엇을 언제 만드는지. 작업을 시작하기 전에 지금 어느 단계인지 이 파일로 확인한다.
> 범위 밖의 기능은 요청받지 않는 한 만들지 않는다. 범위를 바꾸고 싶으면 먼저 물어본다.

## 원칙

- **작게 열고 하나씩 붙인다.** 설계 문서에 있는 기능을 한꺼번에 만들지 않는다. 혼자 운영하는 게임이므로, 오래 끌다 지치지 않는 것이 가장 중요하다.
- **단계마다 실제로 플레이할 수 있어야 한다.** 단계가 끝나면 초대한 사람이 들어와 놀 수 있는 상태여야 한다.
- **신고와 운영자 조치는 첫 오픈부터 있다.** 이용자가 글을 쓰는 순간부터 필요하다.
- **아직 없는 기능의 효과는 건너뛴다.** 예를 들어 v0.1의 갈림길 결과에 "시설 복구 진행"이 있으면, 시설 기능이 생기기 전까지 서버가 그 효과만 건너뛴다 (나머지 결과와 기록은 그대로).

## v0.1 첫 오픈: "캐릭터를 데려와 매일 조금씩 기록이 쌓이고, 그걸로 대화한다"

**가입과 계정**
- 초대 코드 가입, 로그인, 만 14세 이상 확인 항목 (미정 사항이 정해지기 전까지)
- 개인정보 처리방침, 이용약관, 이용 규칙 페이지 (내용은 운영자가 채운다. 자리를 먼저 만든다)
- PWA(홈 화면 추가)와 웹 푸시 알림, 알림 설정

**캐릭터**
- 캐릭터 생성 (역할, 설정 자유 서술, 능력치 배분, 기억상실 정도), 계정당 3명
- 캐릭터 명부(검색), 이미지 업로드 (크기 줄이기, 장수 상한)
- 판독지: 기본 정보, 측정치, 발현 이전 기록(말소 표시), 본인 진술, 오염 기록, 선택 기록, 문답, 관계
- 여러 캐릭터 전환, "지금 말하는 캐릭터" 표시, 오늘 한눈에

**대화**
- 장소 채널 (최근 활동 인원에 따라 여는 수 조절), 1:1 대화, 오너 표시, 머무는 중 표시, 말 걸기 버튼
- 관계 등록 (양쪽 동의, 자관은 바로)

**하루**
- 보내두기 세 가지: 출동(방식 고르기), 근무, 다녀오기. 서버 판정, 성장 굴림
- 오염과 휴식: 혼자 쉬기, 함께 쉬기, 정착지에서 쉬기, 상담·치료 요청(비동기)
- 정화 구역 자동 생성과 정화율 (지도 없이 목록으로)
- 갈림길과 문답 (설정집 "이벤트 스크립트" 탭의 내용을 시드로)
- 물품은 받고 보관만 한다 (쓰임새는 v0.2)
- 매일 접속 보상, 장기 미접속 시 휴식 상태(재단 의료동, 무소속은 정착지)

**운영**
- 신고(글, 이미지, 메시지, 프로필, 문답 답), 차단, 운영자가 숨기기·지우기, 조치 기록(moderation_log), 제재
- 금칙어 검사 (자유 입력: 대화, 캐릭터 설정, 문답 답)
- 운영자 화면 최소판: 신고 목록, 조치, 초대 코드 발급, world_config 수정, 공지

**v0.1에서 열지 않는 자유 입력**: 익명 표식, 오늘의 꾸밈, 교환 게시판 한 마디, 선물 한 마디, 갈림길 답장(C11), 마을 이름 제안(T20). 해당 선택지는 v0.1에서 나오지 않게 하거나 입력 없는 결과로 처리한다.

## v0.2 협동과 물품

- 정화 지도 (서버 정화율, 구역 단계)
- 재단 직원 근무지 복구 진행도, 오늘의 꾸밈 (자유 입력 열림)
- 물품의 쓰임새: 시설에 보태기, 정착지에 보태기
- 주고받기: 건네기, 맞바꾸기 (같은 계정 금지, 받은 물품 재전달 금지, 하루 상한)
- 정착지 등록과 재건 단계, 정착지 이야기 조각, 여행 지도, 길 위의 부탁, 정착지로 보낼 물자
- 모두의 선택을 모으는 갈림길 (F13, F16)

## v0.3 깊이

- 동행 탐색 (실시간, 약속 잡기, 실시간 이벤트), 흔적과 지원
- 익명 표식, 교환 게시판, 꾸미기, 선물
- 단서와 공동 수첩 (단서는 운영자 화면으로 DB에 입력)
- 서사적 퇴장과 구조
- 여행 기록(글·사진), 로그 게시판

## 정해진 것 (2026-11-02)

- 프론트엔드: React + TypeScript (Vite). 함께 쓰는 것은 react-router(해시 라우팅), @supabase/supabase-js, vite-plugin-pwa. UI 라이브러리와 상태 관리 라이브러리는 들이지 않는다 (필요해지면 먼저 묻는다).
- 인증: 이메일 + 비밀번호 (Supabase Auth). 오픈 전에 Supabase 기본 메일 발송 한도를 확인하고, 모자라면 외부 SMTP를 붙인다.
- 개발 순서: 화면 먼저. 데이터 모양은 TypeScript 타입으로 먼저 정하고, 화면은 가짜 데이터 서비스 층 하나를 거쳐 받는다. 처음 온 사람 흐름이 서면 그 부분부터 Supabase에 잇는다.
- 모든 화면은 모바일과 PC 두 배치를 함께 만든다.

## 아직 정해지지 않은 것

- 게임 제목
- 만 14세 미만 가입 처리 (보호자 동의 절차 또는 만 14세 이상 가입)
- 이용 규칙 문서 내용 (플레이어용)
- 밸런스 수치 전체 (초안부터 함께 정한다)
- 서버 구성과 용량 (docs/tech.md "무료 요금제 한도"는 초안)
- 디자인 세부 (글꼴 최종 선택, 상태색, 재단 직원·무소속 판독지 서식)
- 떠난 사람의 기록 처리 (탈퇴한 플레이어의 캐릭터가 남은 사람의 관계, 동행 기록, 로그에 어떻게 남는지)
- 처음 온 사람에게 기능을 하나씩 열어 주는 순서
