# 기술 원칙

> 권장 스택, 알림(PWA·웹 푸시), 무료 요금제 한도, 보안 규칙 상세, 운영과 법, 이용자 콘텐츠 관리.
> 원본은 설정집이다. 이 파일과 설정집이 다르면 설정집이 우선이다. 장 번호(4-1 등)는 파일을 나누기 전의 번호를 그대로 두어 서로 참조할 수 있게 했다.

## 5. 기술 원칙

### 권장 스택

- 프론트엔드: Vite + React + TypeScript. react-router(해시 라우팅), vite-plugin-pwa
- 인증: Supabase Auth, 이메일 + 비밀번호
- 백엔드: Supabase (Postgres, 인증, RLS, RPC 함수, Realtime)
- 배포: **깃허브 페이지** (정적 호스팅). 단일 페이지 앱의 라우팅은 깃허브 페이지에서 새로고침해도 깨지지 않는 방식(해시 라우팅 등)으로 한다.
- 소스는 공개 저장소로 운영한다.
- 다른 스택을 제안하고 싶으면 이유와 함께 먼저 물어본다.

### 알림 (PWA와 웹 푸시)

이 게임은 "나중에 알려 주기"에 기대는 비동기 게임이다 (보내두기 완료, 약속 잡기, 말 걸기, 교환 게시판 결과, 케어 요청). 알림이 오지 않으면 게임이 멈춘 것처럼 느껴지므로 처음부터 만든다.

- **PWA로 만든다**: 웹 앱 매니페스트와 서비스 워커를 두어 홈 화면에 추가할 수 있게 한다. 깃허브 페이지의 하위 경로(저장소 이름)에서도 동작하도록 시작 경로와 서비스 워커 범위를 맞춘다.
- **웹 푸시**: 브라우저의 Push API로 보낸다. 보내는 쪽은 Supabase Edge Function이 맡고, VAPID 비공개 키는 Supabase 비밀값에만 둔다 (저장소와 클라이언트에 넣지 않는다. 공개 키만 클라이언트에 둔다).
- **아이폰**: iOS는 홈 화면에 추가한 웹앱에서만 푸시를 받을 수 있다. 첫 접속 안내에 "홈 화면에 추가하기" 단계를 넣고, 기기별 방법을 그림 없이 짧은 글로 보여 준다. 건너뛸 수 있다.
- **알림 권한은 필요한 순간에 묻는다**: 첫 화면에서 바로 묻지 않고, 처음 보내두기를 했을 때 "끝나면 알려 드릴까요?"로 묻는다.
- **알림 설정**: 종류별로 켜고 끈다 (보내두기 완료, 말 걸기, 약속, 교환, 케어 요청). 밤 시간(초안 23:00~08:00, 한국 시간) 알림은 기본으로 끈다. 밤사이 알림은 아침에 한 번에 묶어 보낸다.
- **묶어서 보낸다**: 짧은 시간에 여러 알림이 생기면 하나로 묶는다 ("끝난 일 3건, 말 걸기 2건"). 알림마다 어느 캐릭터의 일인지 이름을 붙인다.
- **알림이 없어도 놓치지 않게**: 푸시를 끈 사람도 다시 접속하면 "오늘 한눈에"(5-2)에서 모든 결과를 본다.

### 무료 요금제 한도

Supabase 무료 요금제 기준 (2026년 5월 기준 알려진 값. 개발 시작 전에 공식 요금 페이지에서 다시 확인한다): 프로젝트당 DB 500MB, 파일 저장소 1GB, 월 전송량 약 5GB, 1주일 동안 활동이 없으면 프로젝트가 일시 정지된다.

- **이미지가 가장 먼저 찬다**: 업로드 전에 브라우저에서 줄인다 (긴 변 초안 1024px, WebP 변환). 스토리지 정책으로 파일 하나의 크기 상한(초안 500KB)과 형식을 서버에서도 건다. 캐릭터당 이미지 수에 상한을 둔다 (초안 3장).
- **전송량 아끼기**: 이미지는 목록에서 작은 썸네일로 보여 주고, 판독지를 열 때만 원본을 불러온다. 대화 목록은 나눠서 불러온다 (최근 것부터).
- **DB 아끼기**: 만료된 익명 표식, 끝난 교환 게시판 글, 오래된 알림처럼 다시 볼 일이 없는 데이터는 서버 틱이 정리한다. 대화와 로그, 판독지 기록은 지우지 않는다.
- **사용량 보기**: 운영자 화면에 DB, 저장소, 전송량 사용률을 보여 주고, 80%를 넘으면 알린다.
- **일시 정지 주의**: 오픈 전 테스트 기간처럼 접속자가 없는 때에 1주일 이상 비워 두면 정지될 수 있다. 정지되면 대시보드에서 다시 켜야 하므로, 테스트 기간에는 이를 알고 관리한다.

### 보안 규칙 (반드시 지킬 것)

1. **모든 판정은 서버에서 한다.** 보상, 오염 증감, 휴식 정산, 정화 진행도 계산은 서버 함수가 한다. 클라이언트는 "이 행동을 했다"는 요청만 보낸다.
2. **모든 서버 함수 첫 부분에서 권한을 확인한다.** `auth.uid()`로 호출자를 확인하고, 그 캐릭터의 주인인지 검사한다. 관리자 함수는 관리자 테이블로 확인한다.
3. **모든 테이블에 RLS를 켜고 기본은 차단한다.** 쓰기는 서버 함수를 통해서만 한다.
4. **쿨다운과 횟수 제한은 서버에서도 건다.** 클라이언트에서만 막지 않는다.
5. **브라우저에는 anon key만 넣는다.** service_role key는 절대 클라이언트 코드나 저장소에 올리지 않는다.
6. **비밀 설정과 단서 원문은 저장소와 클라이언트 번들 어디에도 넣지 않는다.** 소스가 공개되므로 마이그레이션, 시드, 테스트 데이터, 주석, 커밋 메시지에도 넣지 않는다. 단서는 운영자 화면으로 DB에 입력하고, 서버가 조건부로 내려준다.
7. **소스가 공개된다는 전제로 짠다.** RLS 정책과 서버 함수가 모두 공개되므로, 공개돼도 안전한 구조여야 한다. 비밀값(service_role key, 관리자 계정 정보 등)은 저장소에 절대 커밋하지 않고, `.env` 류 파일은 `.gitignore`에 넣는다.

### 서버 설정값 (world_config)

- 밸런스 수치와 오픈일은 `world_config`에 두고, 운영 화면의 "설정값" 탭에서 묶음(세계, 오염과 폭주, 보상과 회복, 판정·갈림길·성장, 운영)마다 고쳐 저장한다. 기본값은 `src/config/balance.ts`와 `game.ts`, 칸 정의와 허용 범위는 `src/config/worldConfig.ts`에 있다.
- 접속할 때 서버에서 값을 받아 화면의 미리 보기도 같은 값을 쓴다. 저장할 때의 범위 검사(칸끼리의 관계 포함)는 서버가 한다.
- **보내두기의 보상·회복 값은 보낼 때의 값으로 정산한다.** 진행 중인 것은 나중에 값이 바뀌어도 영향받지 않는다. 오염 상태(주의, 폭주, 자연 감소)와 판정 기준은 바로 적용된다.
- 이미 만든 캐릭터와 저장소 정책에 묶인 값(캐릭터 수, 능력치 배분, 이미지 제한, 보내두기 시간, 글자 수)은 보기만 한다. 바꾸려면 코드와 서버 정책을 함께 고친다.
- 바꾼 칸마다 조치 기록에 "설정 변경: 전 → 후"로 남긴다. 플레이어에게 따로 알리지 않는다 (알릴 일은 공지로).

### 운영과 법

이 게임은 개인의 비영리 게임으로 등급분류 면제를 받는 것을 전제로 한다. 면제 조건을 깨는 기능은 만들지 않는다.

- **결제, 광고, 후원하기, 크라우드 펀딩 기능을 넣지 않는다.** 직간접 수익 모델이 하나라도 있으면 면제 대상에서 빠진다. 외부 후원 링크도 넣지 않는다.
- **청소년이용불가 수준의 내용을 넣지 않는다.** 시스템 문구, 이미지, 기본 콘텐츠 모두 해당. 이것도 면제 조건이다.
- 가입을 받으므로 **개인정보 처리방침**과 이용약관 페이지를 둔다. 수집하는 개인정보는 최소한으로 한다.
- 오픈 전에 게임물관리위원회에 면제 여부와, 이용자가 쓴 글·이미지가 등급 판단에 어떻게 반영되는지 확인받는다 (운영자 할 일).
- 멸칭(백지, 실험체)은 롤플레이 안에서만 쓰도록 이용 규칙에 명시하고, 신고 기능을 둔다.

### 이용자 콘텐츠 관리 (필수 기능)

- 글, 이미지, 메시지, 프로필 모두에 신고 기능.
- 운영자가 바로 숨기거나 지울 수 있는 기능.
- **모든 신고와 조치를 기록으로 남긴다** (언제, 무엇을, 어떻게 처리했는지). 운영자가 방치하지 않았다는 근거가 된다.
- 반복 위반자 제재: 경고, 기간 정지, 영구 정지.
- 무거운 주제의 글에 작성자가 "주의" 표시를 달아 접어 둘 수 있게 한다. 단, 접는다고 수위 규칙이 완화되지는 않는다.
